# Project schema compatibility and migration

PR14 introduces an explicit compatibility contract without changing the syntax of any production DSL.

## Project schema manifest

Current projects use:

`/.kide/schema.properties`

Schema version 1 records:

- the project compatibility version;
- the E04 enterprise-context schema version; and
- the compatibility version of DML, Operation, MNC, Capability and Activity models.

The language files themselves are not rewritten merely to add version metadata.

## Compatibility rules

- A project with no schema manifest is a **legacy project** and remains readable.
- A legacy or older supported project can be inspected and dry-run before migration.
- Migration creates or updates only the schema manifest unless a future migration explicitly declares model transformations.
- Existing manifests are backed up before replacement.
- Re-running the same migration is idempotent.
- A project from a newer schema version is rejected as forward-incompatible rather than reinterpreted.
- Missing, malformed, oversized or symbolic-link manifests return typed status/diagnostic information rather than throwing through the Eclipse workbench.
- E04 organization, portfolio, project and workspace IDs are not regenerated by migration.

## Runtime API

`ProjectSchemaService.inspect(projectRoot)` returns a `ProjectSchemaReport`.

`ProjectSchemaService.migrate(projectRoot, dryRun)` performs either a non-mutating migration assessment or a safe migration.

The status values are:

- `LEGACY`
- `CURRENT`
- `MIGRATION_REQUIRED`
- `FORWARD_INCOMPATIBLE`
- `INVALID`
- `IO_ERROR`

## CI qualification

PR14 adds both Tycho/JUnit migration tests and a packaged Linux runtime self-check. The packaged check proves legacy inspection, dry-run non-mutation, migration, idempotence, and forward-version refusal from the actual distributed KIDE application.
